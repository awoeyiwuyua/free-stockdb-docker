# 架构总纲：stockdb-ai（2026-08-16 定稿）

> 本文是**整体架构的存档**（目标 → 边界 → 分层 → 决策 → 演进）。
> 实施细节见 `docs/design/application-layer.md`（四层搬迁）；本文件回答"为什么这样"。
> 定稿依据：用户三轮拍板（①更名 stockdb-ai / AI 后端；②上游只是数据层的一部分；
> ③四层框架先行 / 多源抽象入设计；④U1 产出自持提前 / U2-U4 按建议定稿）。

## 1. 一句话

**stockdb-ai = AI 原生数据后端**：AI 通过 MCP 拿数、程序通过 HTTP 拿数、
上游 free-stockdb 引擎是数据层的 provider 之一（可替换）、研究成果自持存储、
webui 面板仅供人看（冻结）。

## 2. 系统边界

```
AI 客户端（Claude 等）               程序/脚本                人
      ▲ MCP (SSE)                    ▲ HTTP /api/*          ▲ webui 面板（冻结）
      │                              │                        │
      └──────────┬───────────────────┴────────────────────────┘
                 │
        ┌────────┴────────────────────────────────┐
        │            stockdb-ai 应用层              │
        │  接口层：MCP 服务器（53 工具+契约信封）/ HTTP 路由 │
        │  服务层：打板采集/收口/回填 · 同步 · 日检       │
        │  领域层：涨停判定/指标/日历（纯规则）           │
        │  数据层：providers（多源）+ records          │
        └────────┬────────────────────────────────┘
                 │
   ┌─────────────┴──────────────┐   ┌──────────────────┐
   │ 上游引擎（数据层 provider）   │   │ 自建存储（M5 起）   │
   │ stockdb.exe                 │   │ 研究成果自持      │
   │ data/（行情） + mydb/（过渡） │   │ （M5 前暂存 mydb） │
   └────────────────────────────┘   └──────────────────┘
```

**边界纪律**：应用层不感知数据从哪来；上游引擎对应用层只是"行情 provider"；
引擎进程死亡不影响研究成果可读性（M5 产出自持解决——见决策 D8）。

## 3. 分层与归属（定稿）

| 层 | 内容 | 关键归属决策 |
|---|---|---|
| 接口层 | mcp/（MCP 服务器、契约信封、sdk_bridge）+ web/（HTTP 路由，0.9.2） | **sdk_bridge 归接口层**（提供查询服务与结果契约化）；其引擎连接走数据层 |
| 服务层 | services/：打板三用例、同步、日检编排 | **采集编排在服务层**；执行（腾讯/东财抓取）在数据层 |
| 领域层 | core/：涨停判定/指标/日历（纯规则） | 零外部依赖；验收签字资产 |
| 数据层 | storage/providers/free_stockdb.py（引擎）、providers/quote_sources.py（腾讯/东财）、providers/mydb_store.py（研究产出）、records.py | **文件边界按 provider 划分**；统一抽象接口随 M5 |
| 横切 | ops/：日志/告警/调度/健康 | 进程内即可（单进程系统） |

依赖铁律：接口层 → 服务层 → 领域层/数据层；领域层不依赖任何人；数据层不知道"调用者是谁"。

## 4. 关键决策（已定稿）

| # | 决策 | 依据/后果 |
|---|---|---|
| D1 | AI 原生：MCP 核心产品，HTTP 次之 | 用户拍板；MCP 工具面是 1.0.0 契约冻结主体 |
| D2 | 四层 + 横切，依赖单向 | 0.9.1 框架已立；test_layer_boundaries 物理检查 |
| D3 | 数据层多源抽象；上游引擎 = provider（可替换） | 用户拍板；应用层不感知数据来源 |
| D4 | 契约冻结：信封 + 8 错误码 = 对外承诺 | 0.8.x 验收资产；重构永不改变 |
| D5 | 领域层纯规则 | 0.8.14 口径教训 |
| D6 | 本机原生为主，docker 可选 | 用户拍板 |
| D7 | 面板冻结 | ROADMAP 防漂移 |
| D8 | **研究成果产出自持（M5 提前）**：打板指标/序列/清单等研究产出从引擎 mydb 迁出至自建存储（0.9.3） | 引擎进程内 mydb 是最大架构弱点——引擎死 = 数据不可达；自持后引擎仅是行情 provider |
| D9 | **单进程两接口**：MCP 与 HTTP 同进程（webui）；代码保持可拆（web/ 与 mcp/ 物理分开） | 本机单人够用；将来独立 MCP 进程只是启动方式变化 |
| D10 | **sdk_bridge 归接口层**，引擎连接归数据层 free_stockdb provider | 上游引擎被替换时 sdk_bridge 通过 provider 接口仍可用 |
| D11 | **采集执行归数据层**（providers/quote_sources.py），编排归服务层 | 采集用例 = 编排"读清单→调源→算→存" |

## 5. 演进路径（更新）

```
0.9.2  四层搬迁（按 D10/D11 归属）+ 可观测性三件套（日检/探活/结构化日志）
0.9.3  M5 产出自持（D8）：研究产出迁自建存储，mydb 降级为过渡缓存
0.9.x  M6 行情镜像（可选）：关键行情镜像层，上游死时历史可读
1.0.0  契约冻结评审（MCP 工具面 + 数据契约 + 错误码全部签字）
```

## 6. 不做什么（边界红线，沿用 ROADMAP）

- ❌ 不自建行情获取管线（备用底座 = 降依赖，不替代底座）
- ❌ 不做模拟盘/执行类功能；面板不加功能；不换技术栈；不引入付费实时源
- ❌ 0.9.x 不引入独立监控系统（进程内 ops/ 够用）、不引入消息队列/微服务
