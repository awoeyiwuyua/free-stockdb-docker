# 设计草案：通用小清单采集器 + 打板开盘溢价（0.7.0 候选）

> 用户决策：① 数据源参考 [simonlin1212/a-stock-data](https://github.com/simonlin1212/a-stock-data)
> （免费零鉴权、腾讯/mootdx 优先不封 IP、东财独有+限流、备源降级）；
> ② 9:25 集合竞价价 = 当日开盘价（业务口径）；③ 采集器通用化，重点是业务数据存储+读取逻辑。

## 1. 数据源选型

| 用途 | 主源 | 备源 | 说明 |
|---|---|---|---|
| 小清单当日开盘/竞价快照 | 腾讯 `qt.gtimg.cn`（`q=sh600000,sz000001` 一次批量） | 东财 `push2`（单只，限流） | 零鉴权、稳定优先 |
| 涨停池（可选对账用） | 东财 `push2ex` | 同花顺 | 我们清单本地算，不依赖它；仅对账/校验 |

原则：先主源整批拉（失败/超时→重试 1 次→切备源逐只拉），源与降级路径记入 `source` 字段与 errors。

## 2. 存储设计（核心决策：存 mydb，不建新库）

**存 mydb**（用户拍板）：竞价快照是研究原料，mydb 本就是 AI/研究数据区；
写入路径复用港股日K 的 pybao 写库先例；AI 用现成 `get_mydb_data`（前缀通配）直接可读，
**无需新增存储子系统与通用读取工具**。

键结构（命名空间保留前缀，文档约定 AI 勿写）：

```
竞价快照:<YYYYMMDD>:<code> → JSON
{
  "open_price": 9.25 竞价价（口径=当日开盘价，停牌/无竞价 → null）,
  "prev_close": ..., "volume": ..., "amount": ...,
  "source": "tencent" | "eastmoney",
  "contract_version": "auction-snapshot-v1",
  "fetched_at": "2026-08-17T09:26:03", "known_at": "2026-08-17T09:25:00",
  "raw": {...原始响应，通用性由 raw 承载...},
  "state": "captured" | "reconciled",      -- 生命周期内嵌 JSON
  "diff_pct": null, "reconciled_at": null  -- 15:35 对账后回填
}
```

- 存原始快照而非业务结果：通用（任何因子可用）、可重放审计、口径可重算；
- 幂等：同日重跑按 key 覆盖写（batch items），fetched_at 更新；
- 清单提前算：T-1 16:30 算好并落库（K 线当日已同步，清单已定型）。

**清单样本口径**（2026-08-16 对账拍板，与用户仓库 SQL dwd/board_open_feedback_members.sql
及生产 get_board_open_effect_history 判定**同源**，08-14 实测逐位一致：
59 候选 / 12 一字板排除 / 47 有效 / +1.2113% / 成功率 48.94%）：
- 涨停判定 = 收盘价 == round(参考价×(1+10% 或 20%), 2)（精确封板，分位容差）；
  涨幅带近似不可用（炸板股带内误收）；涨跌幅制度由代码段判定
  （创业板 3xx / 科创板 688/689 → 20cm；沪深主板 → 10cm）
- **参考价（0.8.16 异源验收终定口径）**：
  - 普通日 = 上一实际成交日未复权收盘（lag close；引擎 pre_close 被未来除权
    因子回溯污染且不均匀，禁止使用，也禁止统一因子反推——0.8.14 教训）
  - 除权日（复权因子表当日有事件）= 当日 pre_close（法定除权参考价，可信）
  - 停牌跨日/lag 缺失 → 原值兜底；验收：286 找回/4 剔除全命中（新浪 OHLC +
    同花顺终态池）
- 排除：ST、北交所（4/8/92 开头）、非沪深 A 股代码、status≠TRADED、缺价
- 一字板严格定义：昨开/高/低/收全部等于涨停价（T 字板保留，计入采集清单）
- 判定辅助函数直接复用 `mcp.board_metrics`（单一实现，杜绝两套口径漂移）

**业务指标与滚动分位**（用户拍板：获取数据的同时算 60 交易日分位，语义对齐上游
emotion-v1：窗口 60、rank∈[0,1] 越小越弱；**分位与强弱标签口径 2026-08-16 用户拍板**）：

```
打板指标:<YYYYMMDD> → JSON
{ "metrics": {"premium_mean": .., "success_rate": .., "n_samples": ..},
  "rank_60d": {"premium_mean": .., "success_rate": ..},
  "strength_60d": {"premium_mean": "strong|weak|neutral|null", ..},
  "window": 60, "computed_at": ..,
  "value_source": "auction" | "kline" }   # 09:26 竞价版 / 16:30 K线权威版

打板序列:<metric> → JSON   # 分位分母：滚动 60 交易日序列（仅存有效观测）
{ "metric": "premium_mean", "values": [...60..], "dates": [...] }
```

**分位定义**（严格按用户公式，0.8.11 起）：
```
rank = (此前 60 个有效观测中严格低于当日值的天数) / 60
```
- **严格小于**：等值不计入（旧版 count_equal 折半计入已废弃）；
- **分母固定 60**：此前不足 60 个有效观测 → `rank_60d = null`（定义不适用，不硬算近似）。
  因此历史回填日（05-22→08-14）无分位是预期行为；**首个满分母分位出现在序列满
  60 后的首个交易日（回填 60 天后的 08-17 采集日）**；
- **强弱标签**：`strong` rank≥0.90（≥54 个历史观测低于当日）/ `weak` rank≤0.10
  （≤6 个）/ `neutral` 其余；rank 为 null → 标签 null。

- 09:26 采集后立即算当日业务值 → 读序列（近 60 日，全为前值）→ 算分位+强弱 → 写「打板指标」竞价版；
- 16:30 收口：用 K 线算权威业务值 → 追加序列（裁剪至 60）→ 回写「打板指标」K线版
  （两版并存：竞价版供 09:27 决策，K线版供研究/对账）。

## 3. 读取设计（关键）

- **通用出口**：`get_mydb_data`（前缀通配 `竞价快照:<日期>:*`）——AI/研究直接读原始快照，不新增工具。
- **业务派生**：`get_board_open_effect_history` 改造为双源合并：
  - 历史段（T-2 及更早）：涨停判定 + 溢价全部从 kline 算（现逻辑不变）；
  - 当日段（采集表有数据的日期）：涨停判定用 T-1 kline，**溢价 = 采集表 open_price /
    T-1 日收盘价 - 1**（0.8.13：分母统一用 T-1 收盘——采集表 prev_close 在除权
    除息日为交易所调整昨收，混入分红会失真；历史段/回填/收口同一口径）；
  - 信封标注：当日 `known_at="20260817 09:26 竞价采集(source=tencent)"`，历史 `known_at="盘后日K"`；
  - 降级：当日无采集记录 → 回退"截至 T-1" + errors 注明；部分股票失败 → `is_partial=true` + 明细。
- **对账（可信度关键）**：15:35 盘后任务对比"采集 open_price vs kline 开盘价"，差异超阈值（±0.5%）记审计/告警——长期监测"9:25 竞价≈开盘"口径的真实偏差。

## 4. 调度与流程

```
每天 09:26  采集任务：读今日清单（昨日 16:30 算好；缺失时兜底现算）
            ① 腾讯批量拉竞价价（≤50/批，限流≤1req/s）→ 写竞价快照（state=captured）
            ② 算当日业务值（溢价均值/成功率/样本数）→ 读打板序列（近60日）→ 算 60 日分位+强弱
               → 写「打板指标:<今日>」竞价版（value_source=auction）→ 日志

每天 16:30  收口任务（先校验当日同步完成 data_latest_date>=D，未就绪则推迟重试）：
            ① 算明日清单：今日 K 线 → 非一字板涨停 → 写 mydb（清单:<明日>:limitup_non_yizi）
            ② 对账今日采集：今日 9:26 快照 vs 今日 K 线开盘价 → 回写 state=reconciled / diff_pct
               → |diff| > 0.5% → 审计 + 告警（长期监测"竞价≈开盘"口径偏差）
            ③ 用今日 K 线算权威业务值 → 追加打板序列（裁剪 60 日）→ 回写「打板指标」K线版

09:27 起    用户调 get_board_open_effect_history → 当日结果即时出（当日段读 mydb，含分位）
```

## 6. 生命周期与源优先级（中间态收容）

采集快照对"开盘价"字段是**中间态**（先行值），但作为"当日 09:26 的竞价证据"是**终态**。
处理原则：**不删、不改、只转态+对账**。

```
captured（09:26 采集） → reconciled（当日 16:30 对账完成）
                          ├─ 对比 kline 开盘价 → diff_pct 落库
                          ├─ |diff| > 0.5% → 审计 + 告警（长期监测口径偏差）
                          └─ 行职责：竞价证据 + 对账结论（不再作为价格来源）
```

读取源优先级（`get_board_open_effect_history` 及一切派生）：
- **历史日期（已收盘同步）** → 用 K 线（权威终值）
- **今日（同步前）** → 用采集表（唯一可得）
- 信封 `known_at` 永远注明所用源与数据时点

表结构相应增加对账列：`reconciled INTEGER DEFAULT 0, diff_pct REAL, reconciled_at TEXT`。

## 5. 已拍板（2026-08-15）

1. 停牌/无竞价 → `open_price=null`，统计剔除并计入 errors；
2. 清单来源 = 自动计算（T-1 K线），不做手动指定 UI；
