# 运行时模型（后端并发治理）

> 目的：把"谁调谁、多快、依赖卡住时怎么办"制度化为文档，任何新增接口/页面都要
> 对照本模型做一次"运行时影响"评审。源自 0.6.x 多标签切页打瘫后端事故复盘。
> 0.10.0 治理批注：本文由 docs/webui-spa/ 上提至 docs 根（治理制度属全后端），
> 落点已随 0.9.2 四层搬迁更新（闸口迁入数据层；paper 相关行随 0.8.0 模拟盘移除）。

## 1. 核心公式（Little's Law）

```
在途并发 = 到达率 × 单请求耗时
```

服务器 = 有容量上限的队列。三因子（到达率 / 单请求耗时 / 容量上限）至少管住两个，
否则"上游一慢，整体打瘫"。对应治理：

| 因子 | 治理手段 | 落点 |
|---|---|---|
| 到达率 | 前端在途去重、轮询节拍（30s/失焦降频） | `spa/src/api/http.js`、`App.vue` |
| 单请求耗时 | 超时（8~15s）、**熔断器**（连续失败→降级 5 分钟）、**单飞**（并发失效只跑一路） | `app.py: data_latest_date（探针缓存+单飞）`；熔断归闸口（下行） |
| 容量上限 | **信号量**（stockdb 上游并发 ≤8，非阻塞快败；MCP 查询路径 block=True 排队，0.10.0 C1） | `storage/providers/free_stockdb.py: fetch`（原 app.py `stockdb_fetch/_stockdb_gate`，0.9.2 迁入） |

## 2. 依赖地图（API 路径 → 共享依赖 → 最坏耗时 → 治理）

| API 路径 | 扇出到 | 最坏耗时（无治理时） | 治理 |
|---|---|---|---|
| `/api/health` `/api/overview` `/api/status` | `data_latest_date` → stockdb `cmd=vals` ×3~4 前缀 | 40s | 8s 缓存（**含失败**）+ 单飞 + 熔断 + 信号量 |
| `/api/status` | `code_stats` → stockdb `cmd=get 股票代码` | 15s | 15s 缓存（仅成功）+ 熔断 + 信号量 |
| `/api/status` | `data_coverage` → stockdb `cmd=vals` ×36 年份 | 8s×36 | 15min 缓存 + 熔断 + 信号量 |
| `/api/status` | `mirror_latest_date` → 公网镜像页 | 12s | 10min 缓存 + 后台刷新锁（从不阻塞请求） |
| `/api/overview` `/api/version` | `fetch_upstream_release` → GitHub API | 10s | TTL 缓存 + 失败缓存 + 降级 None |
| `/api/overview` | `paper_status_payload` → SQLite 只读 | <10ms | 无（本地） |
| `/api/query`、`stockdb_get`、`_paper_benchmark`、同步校验 | stockdb 直连（控制/用户路径） | 15s | **仅信号量**（限并发不熔断——用户操作不该被探针失败牵连） |
| 启动等待 `_wait_stockdb` | stockdb | 循环 | 直连（启动期不受治理，等待是正确行为） |

## 3. 并发预算（容量上限的量化）

- 浏览器每标签 ≤6 并发连接；假设 3 个标签 + 30s 轮询 + 切页重挂载，
  瞬时并发峰值约 **30~50 请求**。
- ThreadingHTTPServer 每请求一线程（无上限）→ 无治理时峰值线程 = 峰值请求。
- 治理后：打 stockdb 的请求被信号量压到 **≤8 路**；探针熔断后 0 网络等待；
  其余请求全部是本地 SQLite/缓存（毫秒级）→ 线程池实际需求远低于 30。

## 4. 失败模式矩阵（stockdb 状态 × 各接口行为）

| stockdb 状态 | 探针接口（health/status） | 用户查询（/api/query） | 诊断（/api/diag） |
|---|---|---|---|
| 正常 | 缓存+新鲜探测 | 直连 | 六项通过 |
| 慢（同步中） | 前 3 次失败后**熔断 5 分钟**，返回缓存（含"今日待收盘"类降级文案） | 信号量排队，超时 15s 报错 | 服务项显示"熔断开" |
| 挂 | 同上，缓存旧值/None → 面板显示"数据未知"，**不再拖死服务器** | 快速报错 | 服务项异常 |

## 5. 新增功能的"运行时影响"检查清单（必须逐项回答）

1. 新接口扇出到哪些依赖？每依赖最坏耗时多少？
2. 前端调用频率？是否进轮询？多标签是否会放大？
3. 依赖慢/挂时：返回什么？缓存吗（含失败结果）？需要熔断/信号量吗？
4. 该调用是否与探针共用同一依赖？（是 → 必须过 `stockdb_fetch` 闸口）
5. 是否属于控制路径（同步/重启/启动）？（是 → 不接熔断，只过信号量）

## 6. 事故记录

- **0.6.x（2026-08）**：多标签快速切页 → `data_latest_date` 失败不缓存 + 并发无单飞
  + 无界线程 → 请求堆积拖死 ThreadingHTTPServer（用户表现为"卡顿→无法访问此网站"）。
  修复：失败缓存 + 单飞 + 前端在途去重（0.6.3）；熔断器 + 信号量 + 本模型（0.6.4）。
