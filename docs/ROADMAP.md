# ROADMAP — 定位与路线图（2026-08-15 定稿）

> 用户拍板："webui 都不是很需要，我只需要持续打磨 HTTP/MCP，让数据基座做好就行。"
> 本文件是项目的**防漂移锚点**：以后任何新需求先对照这里判断"该不该做"。

## 1. 定位（一句话）

**free-stockdb = 本地量化数据基座；产品形态 = HTTP + MCP 数据接口（可信、只读、可审计）。**

## 2. 各部件职责（冻结版）

| 部件 | 职责 | 状态 |
|---|---|---|
| stockdb 引擎 + 数据更新 | 行情存储与每日同步（原生层） | 运行中 |
| **HTTP API（7899）+ MCP（/mcp，12 只读工具）** | **核心产品：数据接口**，统一契约信封/8 错误码/交易日历 | 持续打磨 |
| 数据契约（信封/时点快照/体检） | 数据可信的基础设施 | 冻结维护 |
| webui 面板（0.6.6） | 辅助驾驶舱（运维/观察模拟盘） | **冻结，不加功能** |
| 模拟盘（159915 固定策略） | 机器执行+审计（60 天观察期 2026-08-17 启动） | 观察期，只修 bug |
| 用户 Mac | 研究工作台（回测/画图/因子试算，用户自己的代码） | 用户侧 |

## 3. 该做什么（按需迭代规则）

1. **接口按需加工具**：用户提出具体研究/因子需求 → 明确所需字段 → 攒批加 MCP 工具/HTTP 端点 → 按发布纪律发一版。
2. **维护**：数据同步/新鲜度/稳定性问题即修（这是数据基座的命根子）。
3. **契约完善**：发现"数据不可信/字段语义不清"就修契约。
4. 观察期（60 个交易日）内：只观察、只维护，不新增任何模块。

## 4. 不该做什么（明确说不）

- ❌ 不给面板加任何新功能/新页面（除非用户明确要求）
- ❌ 不在 NAS 上做回测引擎/因子计算/画图（那是 Mac 的事）
- ❌ 不做备份/恢复模块（等系统里有"不能丢的数据"再提）
- ❌ 不换技术栈（Rust/Go 等——见 2026-08 架构讨论结论）
- ❌ 不引入付费实时行情源（用户已否决）

## 5. 版本计划

- **0.7.0 暂不定义**——等第一个真实的"数据接口需求"（新字段/新工具）出现时再定范围、攒批发版。
- 1.0.0 = 60 天模拟盘验收通过 + 数据契约冻结评审通过。
- 发布纪律见 `docs/webui-spa/release-policy.md`。

## 6. 验收与里程碑

- 短期：60 天模拟盘观察期稳定运行（2026-08-17 起，交易日 08:45–15:05 时间轴 + 情绪文件投递）
- 中期：第一个基于 MCP 的用户研究课题跑通（数据拿得到、拿得可信）
- 长期：数据基座成为用户 Mac 研究流水线的默认数据源
