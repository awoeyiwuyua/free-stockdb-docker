# ROADMAP — 定位与路线图（2026-08-16 升级定稿：stockdb-ai）

> 用户拍板（2026-08-16）：
> ① 项目更名 **stockdb-ai**（原名 free-stockdb-docker）；
> ② 定位 = **AI 友好的后端**（AI 优先的数据接口）；
> ③ **上游 free-stockdb 只是我们数据层的一部分**（多数据源抽象）。
> 本文件是项目的**防漂移锚点**：以后任何新需求先对照这里判断"该不该做"。

## 1. 定位（一句话）

**stockdb-ai = AI 原生数据后端；产品形态 = MCP + HTTP 数据接口（AI 友好、可信、只读、可审计）；上游 free-stockdb 引擎是数据层的 provider 之一，不是架构依赖。**

## 2. 各部件职责（冻结版）

| 部件 | 职责 | 状态 |
|---|---|---|
| **MCP 服务器（/mcp，53 只读工具）** | **核心产品：AI 取数入口**（行情/竞价/因子/基本面/板块/龙虎榜/打板指标/表查询），统一契约信封/8 错误码 | 持续打磨 |
| **HTTP API（webui 路由）** | 程序/脚本取数入口（含打板任务/运维接口） | 持续打磨 |
| 应用层（web/services/core/storage/ops 四层） | 0.9.1 框架已立，0.9.2 搬迁 | 建设中 |
| 数据层（storage/ 多源抽象） | **上游 free-stockdb（行情 provider，当前唯一）** + mydb（研究成果自持）+ 将来自建源 | 0.9.2 设计 |
| 上游引擎 + 数据更新（原生层） | 行情存储与每日同步——**数据层的一部分，可替换** | 运行中 |
| 数据契约（信封/时点快照/体检） | 数据可信的基础设施 | 冻结维护 |
| webui 面板 | 辅助驾驶舱（运维） | **冻结，不加功能** |
| 用户 Mac | 研究工作台（回测/画图/因子试算，用户自己的代码） | 用户侧 |

## 3. 该做什么（按需迭代规则）

1. **AI 友好接口**：用户提出具体研究/因子需求 → 明确所需字段 → 攒批加 MCP 工具/HTTP 端点 → 按发布纪律发一版；工具描述/参数 schema 面向 AI 优化。
2. **维护**：数据同步/新鲜度/稳定性问题即修（数据供给是命根子）。
3. **契约完善**：发现"数据不可信/字段语义不清"就修契约。
4. **数据层扩展**：应用层不感知数据从哪来——加数据源 = 加一个 storage provider。

## 4. 不该做什么（明确说不）

- ❌ 模拟盘已移除（2026-08-15 用户拍板）：不做模拟盘 / 执行类功能，后端只做数据接口
- ❌ 不给面板加任何新功能/新页面（除非用户明确要求）
- ❌ 不在 NAS 上做回测引擎/因子计算/画图（那是 Mac 的事）
- ❌ 不做备份/恢复模块（等系统里有"不能丢的数据"再提）
- ❌ 不换技术栈（Rust/Go 等——见 2026-08 架构讨论结论）
- ❌ 不引入付费实时行情源（用户已否决）
- ❌ 不自建行情获取管线（重造"底座业务"——备用底座的意义是降依赖，不是替代底座）

## 6. 验收与里程碑

- 短期：0.9.x 应用层搬迁完成（四层结构落地、232+ 测试全绿）；打板采集链路稳定运行
- 中期：第一个基于 MCP 的用户研究课题跑通（数据拿得到、拿得可信）；数据层多源抽象
  落地（上游引擎 + mydb 自持双 provider）
- 长期：stockdb-ai 成为用户研究流水线的默认数据后端（AI 客户端一行配置接入）
