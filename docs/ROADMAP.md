# ROADMAP — 定位与路线图（2026-08-16 升级定稿：stockdb-ai）

> 用户拍板（2026-08-16）：
> ① 项目更名 **stockdb-ai**（原名 free-stockdb-docker）；
> ② 定位 = **AI 友好的后端**（AI 优先的数据接口）；
> ③ **上游 free-stockdb 只是我们数据层的一部分**（多数据源抽象）。
> 本文件是项目的**防漂移锚点**：以后任何新需求先对照这里判断"该不该做"。

## 1. 定位（一句话）

**stockdb-ai = AI 原生数据后端；产品形态 = MCP + HTTP 数据接口（AI 友好、可信、只读、可审计）；上游 free-stockdb 引擎是数据层的 provider 之一，不是架构依赖。**

## 2. 各部件职责（冻结版）

| 部件 | 职责 | 状态 |
|---|---|---|
| **MCP 服务器（/mcp，56 工具 = 53 只读 + 3 仓库）** | **核心产品：AI 取数入口**（行情/竞价/因子/基本面/板块/龙虎榜/打板指标/表查询/仓库 SQL），统一契约信封/8 错误码 | 持续打磨 |
| **HTTP API（webui 路由）** | 程序/脚本取数入口（含打板任务/运维接口） | 持续打磨 |
| 应用层（interfaces/services/core/storage/ops 四层） | 0.9.1 框架已立，0.9.2 搬迁，0.9.8 严格分层 | 建设完成 |
| 数据层（storage/ 多源抽象） | **上游 free-stockdb（行情 provider，当前唯一）** + mydb（研究成果自持）+ warehouse（0.10.0 列式仓库：Parquet 沉淀 + DuckDB）+ 将来自建源 | 0.9.2 设计；warehouse 0.10.0 落地 |
| 上游引擎 + 数据更新（原生层） | 行情存储与每日同步——**数据层的一部分，可替换** | 运行中 |
| 数据契约（信封/时点快照/体检） | 数据可信的基础设施 | 冻结维护 |
| webui 面板 | 辅助驾驶舱（运维） | **冻结，不加功能** |
| 用户 Mac | 研究工作台（回测/画图/因子试算，用户自己的代码） | 用户侧 |

## 3. 该做什么（按需迭代规则）

1. **AI 友好接口**：用户提出具体研究/因子需求 → 明确所需字段 → 攒批加 MCP 工具/HTTP 端点 → 按发布纪律发一版；工具描述/参数 schema 面向 AI 优化。
2. **维护**：数据同步/新鲜度/稳定性问题即修（数据供给是命根子）。
3. **契约完善**：发现"数据不可信/字段语义不清"就修契约。
4. **数据层扩展**：应用层不感知数据从哪来——加数据源 = 加一个 storage provider。

## 4. 不该做什么（明确说不）

- ❌ 模拟盘已移除（2026-08-15 用户拍板）：不做模拟盘 / 执行类功能，后端只做数据接口
- ❌ 不给面板加任何新功能/新页面（除非用户明确要求）
- ❌ 不在 NAS 上做回测引擎/因子计算/画图（那是 Mac 的事）
- ❌ 不做备份/恢复模块（等系统里有"不能丢的数据"再提）
- ❌ 不换技术栈（Rust/Go 等——见 2026-08 架构讨论结论）
- ❌ 不引入付费实时行情源（用户已否决）
- ❌ 不自建行情获取管线（重造"底座业务"——备用底座的意义是降依赖，不是替代底座）

- **0.7.0 已发布**（2026-08-15）：打板竞价采集——数据基座首个自取能力（采集→业务值→滚动60日分位→对账），

- **0.8.0 已发布**（2026-08-15）：移除模拟盘——执行 / 研究移出基座，收敛为纯数据接口。
- **0.8.x 已发布至 0.8.18**：验收修正系列（0.8.12~0.8.16 涨停口径终定 + 异源签字）、
  同步链路加固（0.8.17）、仓库治理（0.8.18，原生模式为主线、docker 降级可选）。
- **0.9.0 已发布**（2026-08-16）：SDK 41 工具整合 MCP（sdk_bridge 契约外壳，53 工具，
  本机 41/41 冒烟）+ 边界 c missing_open 计数；log()/DATA_DIR 缺陷修复
- **0.9.1 已发布**（2026-08-16）：应用层四层架构**立框架**——web/services/core/storage/ops
  目录 + 层契约 + 依赖纪律物理检查（test_layer_boundaries.py）+ config.py 提取
- **0.9.2（规划）**：四层**搬迁**（7 批次增量搬，每批测试绿）+ 可观测性三件套
  （打板日检/调度探活与失败告警/结构化日志）+ **storage/ 多数据源抽象**
  （上游引擎 = 第一个 provider；mydb 产出自持 = 第二个；文件边界按 provider 划分）
- **0.9.3 已发布**（2026-08-16）：MCP 工具分组 Gateway（/mcp?group=，6 组 53 工具）+ Trace ID（响应/日志/日检贯穿）；246 测试全绿\n- **0.9.5 已发布（M5 产出自持）**：研究成果迁出引擎 mydb → 自建 SQLite（WAL）——ResearchStore Repository 接口 + 工厂切换（sqlite 默认/mydb 回滚）+ 一次性迁移 + 日检后自动备份；设计见 docs/design/research-store.md
  清单等研究产出从引擎 mydb 迁出至自建存储；引擎进程死亡不再影响研究成果可读性；
  mydb 降级为过渡缓存
- **0.9.8 已发布（2026-08-16）**：严格分层——接口层统一收拢 interfaces/（web/ HTTP + mcp/ MCP），
  领域 shim 清零（core/ 单一真身），层边界测试升级
- **0.9.9 已发布（2026-08-16，D11 落位）**：采集执行迁数据层——auction_collect →
  storage/providers/quote_sources.py（编排在服务层、执行在数据层），契约不变
- **0.10.0 已落地代码（2026-08-22 拍板同日实现，308 测试绿；试运行验收待实数据）**：**列式仓库层（D12，取代 M6 备胎定位）**——
  Parquet 事实沉淀（facts/ 按年/市场/日分区，只增不改）+ DuckDB 查询/计算
  （视图/宏 + run_sql 读写全开三护栏）+ warehouse MCP 工具组 3 个；53 既有工具契约
  不动；数据范围首期 = 日K/复权/代码表；duckdb = 首个第三方依赖（uv 锁定，缺失降级）；
  历史回填不做（仅小范围测试拉取通道）。设计 docs/design/warehouse.md
- **收敛清单（0.10.0 落地时一并执行）**：C1 引擎 HTTP 双轨收归 free_stockdb 闸口；
  C2 查询面收敛（指标一律 SQL 宏，不加单指标工具）；C3 services→warehouse 走注入；
  C4 元数据唯一存 warehouse.duckdb meta；C5 warehouse.duckdb 纳入每日备份
- **延后项登记（防无限挂起）**：仓库历史回填（用户 2026-08-22 延后，另行讨论）；
  分钟K/基本面/龙虎榜数据集（dataset 维度已预留，按需逐个加 sink）；
  hk日k 迁仓库（仓库稳定后，mydb 届时只剩自定义表）；M2 打板情绪衍生指标、
  M3 数据质量看护（仓库 watermark 就绪后对账可复用）继续延后
- 1.0.0 = 数据契约冻结评审通过（架构总纲见 docs/architecture.md）。
- 发布纪律见 `docs/release-policy.md`。

## 6. 验收与里程碑

- 短期：0.9.x 应用层搬迁完成（四层结构落地、232+ 测试全绿）；打板采集链路稳定运行
- 中期：第一个基于 MCP 的用户研究课题跑通（数据拿得到、拿得可信）；数据层多源抽象
  落地（上游引擎 + mydb 自持双 provider）
- 长期：stockdb-ai 成为用户研究流水线的默认数据后端（AI 客户端一行配置接入）
